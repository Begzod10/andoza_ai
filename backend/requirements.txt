# There is deliberately NO USD library here. Pixar's usd-core was deployed and
# its manylinux binaries are killed by SIGILL on the production VPS (a QEMU
# guest whose vCPU has no SSE4.2): prod logged `usdz_to_glb: failed rc=-4`, and
# `Usd.Stage.Open()` reproduces it exactly under `qemu-x86_64 -cpu qemu64`.
# Blender is equally impossible there (official builds refuse to start without
# SSE42; Debian's build has no USD support). The uploaded .usdz is therefore
# archived, never parsed, and the overlay is generated from the parametric scan
# data instead -- which needs only these two, both verified working under
# `qemu-x86_64 -cpu qemu64`.
